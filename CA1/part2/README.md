# Bookstore (Gradle)

This project is the **Bookstore REST API** (Spring Boot + Spring Data JPA + H2 + Spring HATEOAS), originally built with Maven and converted to **Gradle**.

The application provides:

* Management of books, clients and orders (with relationships)
* HATEOAS-based API navigation
* An in-memory H2 database, initialised programmatically with sample data
* An H2 console for database inspection

## Project Goals

This project extends the Gradle concepts explored in Part 1 with a real-world Spring Boot application. It is used to:

* Convert a Maven build into a Gradle build
* Manage dependencies and plugins with a version catalog (`libs.versions.toml`)
* Reuse a BOM (Spring Boot) to manage library versions
* Create custom tasks that orchestrate built-in task types (`Delete`, `Copy`, `Zip`, `Exec`)
* Filter configuration files at build time (`ReplaceTokens`)
* Run an application through the distribution generated by the `application` plugin
* Separate unit tests from integration tests using a dedicated source set

## Prerequisites

To build and run this project, you need:

* Java JDK 17 (toolchain-managed by Gradle)
* Gradle 9 (if the provided Gradle Wrapper is not used)
* Internet access for dependency resolution (Maven Central)

Note: Gradle will automatically download and use JDK 17 via toolchains if it is not installed.

## Build

To build the project:

```
./gradlew clean build
```

This will:

* Compile the source code
* Process the resources (replacing the configuration placeholders)
* Run the unit and integration tests
* Generate the executable Spring Boot JAR (`bookstore-1.0.0.jar`) and the plain JAR (`bookstore-1.0.0-plain.jar`)

## Exploring Available Gradle Tasks

List all tasks:

```
./gradlew tasks
```

List only the custom tasks, by group:

```
./gradlew tasks --group deployment
./gradlew tasks --group application
./gradlew tasks --group documentation
./gradlew tasks --group verification
```

## Run

To run the application:

```
./gradlew bootRun
```

The application starts at `http://localhost:8080`. The task keeps running (the progress bar stays at about 80%) until the server is stopped with `Ctrl+C`, because a web server runs indefinitely.

Main endpoints:

* `GET /` – API entry point with HATEOAS links
* `GET /books`, `GET /clients`, `GET /orders`
* `GET /info/details` – service name, version, environment and build timestamp
* `GET /health`

H2 console: `http://localhost:8080/h2-console`

* **JDBC URL**: `jdbc:h2:mem:bookstore`
* **Username**: `sa`
* **Password**: (leave empty)

## Configuration Placeholders

The service metadata in `application.properties` uses placeholders that are replaced by Gradle with the `ReplaceTokens` filter:

```
service.version=@projectVersion@
service.environment=@environment@
service.build.timestamp=@buildTimestamp@
```

* In local runs (`bootRun`, tests, `installDist`) they are replaced by `processResources` with the project version, `local` and `local-build`.
* In the dev deployment (`deployToDev`) they are replaced with the project version, `dev` and the current timestamp.

## Deploying to the Development Environment

To create a deployment in `app/build/deployment/dev`:

```
./gradlew deployToDev
```

This task orchestrates four tasks:

1. `cleanDevDeployment` (`Delete`) – cleans the deployment directory
2. `copyAppToDev` (`Copy`) – copies the application JAR
3. `copyLibsToDev` (`Copy`) – copies the runtime dependencies into `lib/`
4. `copyConfigToDev` (`Copy`) – copies the `.properties` files, replacing the placeholders

Resulting structure:

```
app/build/deployment/dev/
├── application.properties
├── bookstore-1.0.0-plain.jar
└── lib/
```

To run the application from the deployment directory:

```
cd app/build/deployment/dev
java -cp "bookstore-1.0.0-plain.jar:lib/*" com.example.bookstore.BookstoreApplication
```

On Windows, replace `:` with `;` in the classpath separator.

The external `application.properties` takes precedence over the one inside the JAR, so `/info/details` shows `environment = dev` and the deployment timestamp.

## Running from the Distribution

To run the application using the start scripts generated by the `application` plugin:

```
./gradlew runDist
```

This task depends on `installDist` (which generates `app/build/install/bookstore`) and selects the start script according to the operating system: `bin/bookstore.bat` on Windows and `bin/bookstore` on Linux/macOS.

Note: on Windows, the generated `.bat` file is adjusted by the build to use a classpath wildcard (`lib\*`), avoiding the `The input line is too long` error caused by the large number of dependencies.

## Javadoc

To generate the Javadoc and package it into a zip file:

```
./gradlew javadocZip
```

The documentation is generated in `app/build/docs/javadoc/index.html` and the archive in `app/build/docs-zip/bookstore-1.0.0-javadoc.zip`.

## Testing

Run only the unit tests:

```
./gradlew test
```

Run only the integration tests (separate `integrationTest` source set, which starts the full Spring context):

```
./gradlew integrationTest
```

Run both:

```
./gradlew check
```

Test reports are available in `app/build/reports/tests/test/index.html` and `app/build/reports/tests/integrationTest/index.html`.
